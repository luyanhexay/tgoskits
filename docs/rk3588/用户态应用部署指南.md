# RK3588 用户态应用开发 & StarryOS 部署指南

## 概述

所有用户态程序需要在 RK3588 Linux 上编译调试（板端有完整运行时环境和 WiFi），
然后将编译好的二进制及依赖库部署到 StarryOS rootfs 中。

**硬件**: Orange Pi 5 Plus (RK3588)，16GB/32GB eMMC，M.2 WiFi 模块。

**物理连线**（参考 `环境准备.md`）:

| 接口 | 连线 | 用途 |
|------|------|------|
| Type-C（靠近网口） | Type-C ↔ PC USB | 烧录/Maskrom 模式 |
| 串口（3-pin 排针） | USB-TTL ↔ PC | U-Boot / 串口终端（波特率 1500000） |
| 以太网口 | 网线 ↔ PC（或局域网） | TFTP 加载内核 |
| DC 电源 | 5V/4A 适配器 | 供电 |

> 板子通过 U-Boot + TFTP 从主机加载 StarryOS 内核，以 eMMC ext4 分区作 rootfs。
> 详见 `从0启动.md` 和 `1.sh`。

## 一、下载并烧录板端 Linux

板端需要先运行一个完整的 Linux 系统（Orange Pi 官方镜像，基于 Rockchip BSP），
用于编译和调试用户态程序。

### 1.1 下载官方 Linux 镜像

Orange Pi 5 Plus 的官方镜像基于 Rockchip RK3588 BSP SDK，带完整的 NPU 驱动、
UVC 驱动和 WiFi 支持。

**下载地址**:

- **Orange Pi 官方下载页**: http://www.orangepi.org/html/hardware/computerAndMicrocontrollers/service-and-support/Orange-pi-5-plus.html
- **推荐镜像**: `Orange Pi 5 Plus Ubuntu 22.04 (Jammy) Gnome Desktop` 或 `Orange Pi 5 Plus Debian 12 (Bookworm)`
- **选择依据**: 优先选 Ubuntu 22.04 — Rockchip 的 BSP 内核和 NPU 驱动对此版本兼容性最好，且软件源齐全

在官方页面上找到 "Linux 镜像" 区域，选择对应镜像下载（.img.xz 或 .img.gz 文件）。

> **瑞芯微官方 SDK 渠道**（进阶需求）:
> 如果要自行编译内核或定制 BSP，可以从瑞芯微官方获取 SDK：
> - RK3588 Linux BSP SDK: https://github.com/rockchip-linux
> - RKNN Toolkit & NPU 驱动: https://github.com/airockchip
> - 预编译固件: 瑞芯微 Wiki → https://opensource.rock-chips.com/wiki_Linux_BSP
>
> 一般开发不需要自行编译，直接用 Orange Pi 官方镜像即可。

### 1.2 准备烧录工具

在 **主机**（PC, x86_64 Linux）上安装 `rkdeveloptool`:

```bash
# 安装依赖
sudo apt install -y build-essential libusb-1.0-0-dev

# 克隆并编译
git clone https://github.com/rockchip-linux/rkdeveloptool.git
cd rkdeveloptool
autoreconf -i
./configure
make -j$(nproc)
sudo make install
sudo ldconfig
```

或者直接从包管理器安装（如果发行版有）:

```bash
sudo apt install rkdeveloptool
```

### 1.3 进入 Maskrom 烧录模式

1. **断电**（拔掉 DC 电源）
2. 按住板子上的 **Maskrom 按键**（位于 Type-C 烧录口旁边）
3. 用 **Type-C 线连接 PC 和板子**（注意：是靠近网口的那个 Type-C 口）
4. 松开 Maskrom 按键
5. 确认 PC 识别到设备:

```bash
# 应看到 Rockchip 设备
lsusb | grep -i rock
# 输出类似: Bus 003 Device 012: ID 2207:350a Fuzhou Rockchip Electronics Company

# rkdeveloptool 也能识别
sudo rkdeveloptool ld
# 输出: DevNo=1	Type=Maskrom
```

### 1.4 烧录镜像到 eMMC

```bash
# 解压下载的镜像
xz -d Orangepi5plus_*.img.xz   # 或 gzip -d

# 写入 eMMC（注意: 会覆盖整个 eMMC，约 10-15 分钟）
sudo rkdeveloptool wl 0 Orangepi5plus_*.img

# 等待写入完成后重置设备
sudo rkdeveloptool rd
```

> **替代方案 — SD 卡烧录**:
> 如果手上没有 Type-C 烧录线，也可以把镜像烧录到 SD 卡（用 balenaEtcher / `dd`），
> 插入板子 SD 卡槽后上电。板子会优先从 SD 卡启动 Linux。
> ```bash
> # SD 卡烧录示例
> sudo dd if=Orangepi5plus_*.img of=/dev/sdX bs=4M status=progress conv=fsync
> ```
> SD 卡方法的缺点: eMMC 仍然需要额外步骤才能写入 rootfs，在板端 Linux 里用 `dd` 或
> `rkdeveloptool` 再烧一次 eMMC 即可。

### 1.5 首次启动和 WiFi 配置

板子上电后，串口终端（minicom，波特率 1500000）会输出 Linux 引导日志。
进入系统后配置 WiFi:

```bash
# 默认用户名/密码: orangepi/orangepi

# WiFi 连接（NetworkManager）
nmcli dev wifi connect "<SSID>" password "<密码>"

# 或交互式
nmtui
```

## 二、板端环境准备

### 2.1 确认板端 Linux 联网

```bash
# 板端 Linux
ip -br addr                          # 查 IP
ip -br addr show wlan0               # WiFi IP
```

假设板端 IP = `192.168.1.101`（按实际调整）。

> **直连方式（无路由器）**: 主机和板子用网线直连时，在主机上配置静态 IP:
> `sudo ip addr add 192.168.1.100/24 dev <网口>`，见 `从0启动.md`。

### 2.2 安装编译依赖

```bash
ssh orangepi@192.168.1.101

# 基础工具
sudo apt update
sudo apt install -y build-essential cmake pkg-config git

# 摄像头 + 图像
sudo apt install -y libusb-1.0-0-dev libuvc-dev libturbojpeg-dev

# 音频 (yolov8 utils 编译需要)
sudo apt install -y libsndfile1-dev

# RKNN 库（板端镜像一般预装，确认一下）
ls /usr/lib/librknn*.so
# 应看到 librknnrt.so 和 librknn_api.so，没有则从 RKNN SDK 安装
```

## 三、开发调试工作流

### 核心思路

```
主机写代码 → SCP/rsync 传到板端 → 板端 cmake/make 编译 → 运行测试 → 迭代
                 ↑                                                    |
                 └────────── 改代码后重新 rsync ←───────────────────┘
                                                              ↓
                                                      测试通过 →
                                                    二进制+.so+.rknn 部署到 StarryOS
```

### 3.1 克隆源码到板端

```bash
# 板端
mkdir -p ~/tgoskits-apps && cd ~/tgoskits-apps

# 克隆主程序
git clone https://github.com/pengzechen/aka-rk3588.git

# 克隆 yolov8 依赖（放到 aka-rk3588 同级目录）
git clone <yolov8-rknn-repo-url> yolov8
# 注意: yolov8 仓库 URL 需确认，它需要和 aka-rk3588/../yolov8 对应
```

> 如果 yolov8 已经随板端镜像预装在某处，创建符号链接即可：
> `ln -s /path/to/yolov8 ~/tgoskits-apps/yolov8`

### 3.2 在板端编译

```bash
# 板端
cd ~/tgoskits-apps/aka-rk3588

# 方式 1: 一键脚本
./build_rk3588.sh

# 方式 2: 手动 cmake (native 模式)
mkdir -p build && cd build
cmake .. \
  -DCMAKE_BUILD_TYPE=Release \
  -DNATIVE_BUILD=ON \
  -DTARGET_SOC=rk3588 \
  -DLOG_LEVEL=INFO
make -j$(nproc)
```

产物: `build/tennis`

### 3.3 分步测试

```bash
# 1. 先测摄像头是否正常
sudo ./build/tennis test-uvc 0
# 应生成 capture.jpg

# 2. 测 NPU 推理
sudo ./build/tennis test-yolo /path/to/tennis.rknn 0
# 应生成 result.jpg（带检测框）

# 3. 测电机（UART 接 ESP32-C3）
sudo ./build/tennis test-motor /dev/ttyS3
# 或手动指定转速:
sudo ./build/tennis test-motor /dev/ttyS3 m1=200 m2=200
```

### 3.4 主机→板端快速迭代

每次在主机上改完代码后：

```bash
# 主机端一键: 上传源码 + 编译 + 测试摄像头
rsync -avz --exclude='build' \
  ~/Projects/aka-rk3588/ orangepi@192.168.1.101:~/tgoskits-apps/aka-rk3588/ && \
ssh orangepi@192.168.1.101 \
  'cd ~/tgoskits-apps/aka-rk3588 && ./build_rk3588.sh && sudo ./build/tennis test-uvc 0'
```

### 3.5 调试技巧

```bash
# 查看二进制依赖
ldd build/tennis

# 查看 USB 设备
lsusb
ls -l /dev/bus/usb/
ls -l /dev/tty*          # 串口设备

# 抓取 UVC 原始帧 (用 uvc-fps)
sudo ./uvc-fps --device 0 --format mjpeg --duration-sec 3 --save-dir /tmp/

# 系统调用跟踪
sudo strace -f ./build/tennis test-uvc 0 2>&1 | head -100
```

## 四、部署到 StarryOS

### 4.1 收集部署文件

```bash
# 板端
cd ~/tgoskits-apps/aka-rk3588

# 1. 收集二进制依赖的 .so
mkdir -p ~/deploy-libs
ldd build/tennis | grep '=> /' | awk '{print $3}' | while read lib; do
  cp -a "$lib" ~/deploy-libs/
done

# 2. 确认所有依赖都已收集（不要有 "not found"）
ldd build/tennis | grep 'not found'
# 如有缺失，手动查找并复制
```

### 4.2 写入 StarryOS rootfs（板端直接操作）

板端 Linux 和 StarryOS 共享同一个 eMMC rootfs 分区 (`mmcblk0p2`)，
在 Linux 下挂载后直接写入：

```bash
# 板端 Linux
sudo mount /dev/mmcblk0p2 /mnt

# 部署 tennis 主程序
sudo cp ~/tgoskits-apps/aka-rk3588/build/tennis /mnt/usr/bin/

# 部署 NPU 模型
sudo cp ~/tgoskits-apps/tennis.rknn /mnt/root/

# 部署 uvc-fps
sudo cp ~/tgoskits-apps/uvc-fps /mnt/usr/bin/

# 部署运行时库（用 cp -a 保留符号链接）
sudo cp -a ~/deploy-libs/*.so* /mnt/usr/lib/

# 验证
ls -l /mnt/usr/bin/tennis
ls -l /mnt/root/tennis.rknn

sudo umount /mnt
```

> 不需要重刷 rootfs，改动即时生效。

## 五、运行时库速查

`app/runtime_lib/` 已有（也是部署到 `/usr/lib/` 的最小集合）：

| 文件 | 用途 |
|------|------|
| `libuvc.so.0` | USB 视频类协议 |
| `libusb-1.0.so.0` | USB 设备访问 |
| `libudev.so.1` | 设备枚举 |
| `librkuvc.so` | Rockchip UVC 优化 |
| `librknn_api.so` + `librknnrt.so` | Rockchip NPU |
| `libturbojpeg.so.0` | JPEG 编解码 |
| `libjpeg.so.8` | JPEG 库 |
| `libdrm.so.2` | DRM 渲染 |
| `libstdc++.so.6` | C++ 标准库 |
| `libc.so.6` + `libm.so.6` + `libpthread.so.0` + `libdl.so.2` | C 运行时 |
| `libgcc_s.so.1` | GCC 运行时 |
| `ld-linux-aarch64.so.1` | 动态链接器 |

新引入库时：

```bash
# 板端查缺
ldd ./binary | grep 'not found'
# 找到后复制
cp -a /path/to/libxxx.so* ~/deploy-libs/
# 部署
sudo mount /dev/mmcblk0p2 /mnt
sudo cp -a ~/deploy-libs/*.so* /mnt/usr/lib/
sudo umount /mnt
```

## 七、常见问题

### 编译找不到 yolov8 头文件
板端需要 `yolov8` 仓库在 `aka-rk3588/../yolov8`，检查目录结构：
```bash
ls ~/tgoskits-apps/yolov8/examples/yolov8/cpp/postprocess.cc
```

### StarryOS 中 "library not found"
确认 .so 文件在 `/usr/lib/`：
```bash
ls -l /usr/lib/libuvc.so*
ls -l /usr/lib/librknnrt.so
```

### USB 摄像头无法打开
StarryOS 需要 usbfs 支持，确认 `/dev/bus/usb/` 目录存在且有设备节点。

### 机械臂 (UART) 尚不可用
当前 `tennis.cpp` 主状态机中 arm/gripper 标记为 TODO，UART 舵机驱动框架已就绪但未集成到主循环中，需后续开发。

### 烧录时 `rkdeveloptool` 找不到设备

确认:
1. Type-C 线插在**靠近网口**的那个 Type-C 口（不要插到 USB 3.0 旁边的 Type-C）
2. 进入 Maskrom 模式步骤是否正确: 断电 → 按住 Maskrom 键 → 插 Type-C → 松键
3. `sudo rkdeveloptool ld` 需要 root 权限

如果还是不行，在主机上检查内核日志:
```bash
dmesg | tail -20
# 应看到 "New USB device found: ... Rockchip"
```

### Linux 烧录后无法启动 / 黑屏

1. 检查串口输出 (minicom, 1500000 波特率)，看 U-Boot 是否有报错
2. 确认镜像文件没有损坏: `md5sum Orangepi5plus_*.img`
3. 可能是 eMMC 分区表损坏，用 SD 卡启动后重新烧录 eMMC

### 板端串口设备对照

| 设备 | 用途 | 说明 |
|------|------|------|
| `/dev/ttyS2` | Linux 控制台 | U-Boot `console=ttyS2,1500000` |
| `/dev/ttyS3` | ESP32-C3 电机控制 | tennis `-motor` 的默认参数 |
| `/dev/ttyUSB0` | USB-TTL 串口 (主机侧) | minicom 使用 |
| `/dev/ttyFIQ0` | FIQ 调试串口 | RK3588 fiq-debugger，内核调试用 |
